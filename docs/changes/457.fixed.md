- **A Postgres `infinity` timestamp no longer breaks pages or jobs (#457).** BunMail never writes one, but a hand-edited row can hold `infinity` or `-infinity`, and since Bun 1.4.4 it reaches the app as the number `Infinity` instead of a `Date`. Every dashboard timestamp (`TimeDisplay`, the audit log, the opens and clicks timeline) now shows its fallback (`n/a`, `Never`, `Permanent`) instead of failing with a 500, and the inbound reply quote drops the date. The trash purge no longer fails on such an email: its tombstone records no sent or deleted date. The domain re-check writes `verified_at` only when it changes, so an `infinity` one stays as stored instead of failing every run. A click on an email whose `sent_at` is `infinity` is recorded (without the just-sent scanner window) instead of failing to record. The API already serialized these values as `null`, the CSV export as empty cells and the export cursor as Postgres text; expiry checks run in SQL, where `infinity` never expires and `-infinity` already has. A new helper `finiteDate` (`src/utils/finite-date.ts`) maps a non-finite value to "no date". Docs: `docs/dashboard.md`.
