- **DANE no longer drops the MTA-STS certificate check on hosts with no usable TLSA record (#452).** With `DANE_ENABLED=true`, an MX host whose DNSSEC-signed TLSA records are all unusable (only DANE-TA under Bun 1.3.14, or only PKIX usages) got TLS with any certificate, even when the recipient domain's MTA-STS policy was in enforce mode, where DANE off would have required a valid certificate naming the MX host. DANE now takes precedence over MTA-STS only where DANE validation happens (RFC 8461 section 2): such a host gets the enforce policy's treatment (skipped when the policy does not name it, else STARTTLS required and the certificate verified for the MX host), and stays at required but unauthenticated TLS only without an enforce policy (RFC 7672 section 2.2). Hosts with a usable record keep DANE, unchanged. The `mx.session` span's `bunmail.mx.dane_mode` reads `mta-sts` for these sessions, and a `debug` line `DANE: no usable TLSA record, MTA-STS verified TLS applies` names the domain and MX host. See `docs/emails.md` (DANE, Precedence).
