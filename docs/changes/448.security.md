- **Dashboard failure logs no longer carry query parameters or addresses (#448).** Several dashboard catch blocks logged an error's raw message: a failed send's database error embeds its query parameters (sender, recipients, subject), a failed API key create its allowed senders, and a failed domain add or DKIM rotation step the domain's encrypted DKIM private key. They now log `loggableError(error)` (the SQLSTATE only) with the user, key, domain or template id. A send the API would refuse with a code (suppressed recipient, sender off the key's allowlist, revoked key, invalid input) logs at `warn` with that code, never the address it carries, instead of at `error` with its message. A failed template or webhook delete, which logged nothing, now logs at `error`. The account pages' shared `errorMessage` helper reduces a database error the same way, since not every service they call sanitizes its own.
  - Docs: `docs/logging.md`.
