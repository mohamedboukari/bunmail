- **Integration test runs no longer collide on ports (#443).** The integration tests started their SMTP servers on fixed ports (12465, 12587 to 12641), so two runs on one machine at once (two pre-commit hooks, or parallel agents with their own databases) failed with `EADDRINUSE`. Every test listener now binds port `0` and reads the real port back (never below 10000), and a unit test fails on any hard-coded listener port under `test/`. The migration-lock test created its throwaway databases under fixed names (`bunmail_migrate_lock_1`, `_ok`, `_fail`) and dropped them `WITH (FORCE)`, so one run could drop another's mid-test; they are now named after the run's own database (`<db>_ml_ok`, checked to be a plain identifier within 63 characters), the cleanup drops only this run's, and its timeout allows for slow `DROP DATABASE` checkpoints on a busy server. To read the port, the inbound and submission services gain `listeningPort()`, and their start lines (and the app's `BunMail server started` line) log the bound port; with a real configured port, as in production, nothing changes. Docs: `docs/testing.md`, `docs/inbound.md`, `docs/smtp-submission.md`.
