- **Retired the Bun 1.3.14 workarounds that Bun 1.4.4 makes unnecessary (#456).** Follow-up of the Bun 1.4.4 upgrade (#447). A new unit test, `test/unit/bun-runtime.test.ts`, pins the runtime fixes the code now relies on and fails on Bun 1.3.14, so a Bun upgrade that brings one back fails CI (and the weekly canary run warns first).
  - The implicit-TLS submission listener no longer guards every socket against being half-closed (#351): under Bun 1.3.14 a TLS socket ended then paused stayed in `CLOSE_WAIT` and spun a CPU core once the client hung up; Bun 1.4.4 closes it, and the pinned smtp-server resumes a socket it unpipes. The `SMTP submission client hung up` debug line goes with the guard; the hang-up integration tests still pass at every stage, on Linux and macOS.
  - CSV exports: Bun 1.4.4 pulls a streamed response only as the client reads (a few MB ahead), and its idle timeout (30 s) cancels a client that stops reading, which frees its export slot. The row cap and the 2 exports per process stay, now described as limits on database load and memory rather than as the only bound on a fully buffered file.
  - Kept, with the reason now in the code: the check that refuses a STARTTLS handshake with no cipher or no certificate for DANE (free, and it fails closed should the runtime regress), the 60 s STARTTLS stall limit (nodemailer clears its setup timer once TLS is up, so without it a peer that goes silent after the handshake would hold the session and its MX lock for 10 minutes), and the `AsyncLocalStorage` rule (only `run`, never `enterWith`), now for scoping: a context cannot leak into later work.
  - `DATABASE_POOL_MAX` docs no longer say the pool can stall: Bun 1.4.4 fixed that (#447), and the setting is now for pool sizing and the connection budget (`.env.example`, `docs/self-hosting.md`, `docs/testing.md`, `ARCHITECTURE.md`).
