- **Changelog entries are fragments under `docs/changes/`, so parallel PRs no longer conflict on `CHANGELOG.md` (#442).** Every PR used to add its entry right under `## [Unreleased]`, so two PRs built from the same `main` always conflicted there. A PR now adds `docs/changes/<issue>.<type>.md` (`<type>`: `added`, `changed`, `deprecated`, `removed`, `fixed` or `security`; extra fragments take a slug, `<issue>.<type>.<slug>.md`) holding its bullet exactly as it should appear in the changelog. `bun run changelog:collect [X.Y.Z]` writes the fragments into `CHANGELOG.md`, grouped by type in the changelog's section order and merged into the existing subsections, under `[Unreleased]` or, with a version, under a new `## [X.Y.Z] - <date>` heading, then deletes them; the `/release` skill runs it in its CHANGELOG step. A new `changelog` CI job (`bun run changelog:check`) fails a PR that changes `src/`, `drizzle/`, `Dockerfile`, `docker-compose*.yml` or `.env.example` without adding a fragment (or changing `CHANGELOG.md`, for a release PR), unless it carries the `skip-changelog` label, and refuses a malformed fragment. The entries already under `[Unreleased]` stay where they are.
  - Docs: `docs/changes/README.md`, `CLAUDE.md`, `CONTRIBUTING.md`, `docs/testing.md`, the PR template and the `/ship` and `/release` skills.
