- **Bun 1.3.14 to 1.4.4 (#447).** The `Dockerfile` (all stages) and CI now run Bun 1.4.4 (`@types/bun` 1.4.4 in `bun.lock`). It fixes the Postgres pool stall found in #423: with more queries in flight than the pool has connections and some of them statements a connection had not prepared yet, Bun 1.3.14 could leave queries pending forever while Postgres showed every connection idle (30 concurrent first-time statements against the default pool of 10 stalled in the first round on 1.3.14, never in 600 rounds on 1.4.4). Self-hosters: `docker compose up -d --build` picks up the new base image; run `bun upgrade` locally to match.
  - A Postgres `infinity` timestamp now reaches the app as the number `Infinity` instead of an invalid `Date`; the CSV export writes it as an empty cell, as before.
  - Rechecked the 1.3.14 workarounds: fixed upstream in 1.4.4 are the `enterWith` crash in Elysia hooks, the eager draining of streamed responses, the half-closed implicit-TLS socket left in `CLOSE_WAIT` (#351), server-side STARTTLS (#414), the ignored `localAddress`, a refused TLS handshake reaching the secure callback, and the hidden peer certificate chain (DANE-TA). All guards stay for now; DANE-TA stays off until it is switched on in its own change. Still needed: the own TXT resolver (`resolveTxt` still splits multi-string records, oven-sh/bun#44692), the manual handshake timeout of the implicit-TLS listener, the nodemailer patch and the jsonb encoding fix (bun-sql encodes jsonb exactly as before, rows written by 1.3.14 read back unchanged).
