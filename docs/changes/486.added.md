- **Attachments of received emails in the dashboard and the API (#486).** The inbound detail page lists the attachments of a received email (name, type, size, inline Content-ID) with a download link, for live and trashed mail, and the API gains `GET /api/v1/inbound/:id/attachments` and `GET /api/v1/inbound/:id/attachments/:position` (admin keys), with `attachments` on `GET /api/v1/inbound/:id`. They are parsed from the stored raw message when asked for, so mail received before this release shows them too, with no migration. Downloads are always a forced `application/octet-stream` attachment with `nosniff` and a sandbox CSP, as for outbound attachments.
  - `scripts/seed-inbound.ts` sends sample messages (attachments, inline image, remote images, risky HTML) into a local inbound server for manual testing.
