- **Verified feedback-loop complaints must also come from a configured sender (#471).** With `SUPPRESSIONS_SHARED_HARD=true`, a complaint is shared across API keys only when its report is verified. A verified report must now also come from an address listed in the new `FEEDBACK_LOOP_SENDERS` (exact addresses or `@domain`), its passing DKIM signature of a `FEEDBACK_LOOP_DOMAINS` domain must be aligned with its `From` domain, and a non-empty envelope sender must be listed too. The `From` and top-level `Content-Type` checked are the ones the signature covers, read the way the DKIM verifier reads them; a report with more than one of either is not verified, and the `From` must be plainly one ASCII mailbox. The report body is parsed in its relaxed-canonical form, so whitespace changes a relaxed signature tolerates cannot change the email or recipient a report names. Boot warns when `FEEDBACK_LOOP_DOMAINS` lists a consumer mailbox domain or a subdomain of one, and refuses `@domain` for one in `FEEDBACK_LOOP_SENDERS`.
  - **Upgrade note:** with `FEEDBACK_LOOP_DOMAINS` set and `FEEDBACK_LOOP_SENDERS` empty, no new complaint is verified (boot logs a warning). Set `FEEDBACK_LOOP_SENDERS` to the `From` address of each provider's reports, taken from a real report's headers (see `docs/feedback-loops.md`). Complaints already stored as verified stay verified.
