- **Background services no longer log or store a database error's query parameters (#458).** The email queue, the webhook delivery worker, the inbound SMTP and submission listeners, inbound notifications, the trash purge, the DNSBL and DANE resolver self-checks, the sending-IP check, session location and the boot and maintenance scripts logged an error's raw message in 38 places. A drizzle query error's message embeds the query and its bound values (recipients, senders, subjects, a webhook consumer's reply), so these lines now go through `loggableError` (the Postgres SQLSTATE only); other errors keep their message, and the API's catch-all `Unhandled error` line does the same. A send that fails on a database error before reaching an MX host (the domain lookup, the suppression re-check before a retry, the attachments load) used to store that message in `emails.last_error`, shown in the dashboard and the API, and copy it into the `email.failed` webhook payload: both now carry `Database query failed (SQLSTATE <code>)`. An input error keeps its fixed message, and an MX host's SMTP reply is stored as before. An inbound notification that cannot be sent (a DKIM key that cannot sign) logs at `warn` with the error's class.
  - Docs: `docs/logging.md`, `docs/emails.md`.
